# Direct Customer Completion

## Scope

This stage completes Platform-managed direct Customer onboarding before the
remaining Dealer workflow.

A direct Customer is represented by:

```text
Customer
managingDealerId = null
acquisitionSource = DIRECT
CustomerDealerAssignment.managementType = PLATFORM
```

## Backend API

The management web panel uses:

- `GET /api/v1/customers`
- `POST /api/v1/customers/individual`
- `POST /api/v1/customers/organization`
- `GET /api/v1/customers/:customerId/members`
- `POST /api/v1/customers/:customerId/members`

Permissions:

- `customer.view`
- `customer.create`
- `customer.update`

The backend remains authoritative for scope validation and immutable auditing.

Audit actions include:

- `customer.individual.created`
- `customer.organization.created`
- Customer-member provisioning audit generated by the Customer service.

## Customer types

### Individual

- full name;
- primary mobile;
- primary email;
- date of birth;
- emergency contact.

### Organization

- legal name;
- display name;
- primary contact;
- registration number;
- tax reference;
- contact person.

## Customer Owner

The primary login is provisioned with:

```text
role = CUSTOMER_OWNER
scopeType = CUSTOMER
scopeId = selected Customer
```

New identities require a strong temporary password. Existing identities can be
attached by mobile number without changing their password.

## Web BFF

Browser requests use `/api/management/customers...`.

The BFF:

- reads HttpOnly authentication cookies;
- refreshes expired access tokens;
- never exposes access or refresh tokens to client JavaScript;
- validates basic input before forwarding;
- preserves backend permission and scope enforcement.

## Live review

After this feature is installed, the setup restarts the permanent live
development environment at:

```text
http://localhost:3001/management/customers
```

Routine review uses hot reload. No feature-specific preview script is needed.
